[[nitriteTransactions]]
== Transactions

Nitrite integrates with Micronaut's `@Transactional` infrastructure through api:data.nitrite.transaction.NitriteTransactionOperations[]. When a transaction is active, repository calls participate in the same Nitrite transaction and are committed or rolled back together, whichever storage engine backs the datasource. Keep units of work short to avoid blocking other threads that need to mutate the store.

Transaction and connection operations exist once per configured datasource. A transaction therefore covers exactly the datasource it was opened against; see <<nitriteConfiguration, Multiple Datasources>>.

NOTE: To select a named datasource's `NitriteTransactionOperations` or `NitriteConnectionOperations`, use a `@Named` qualifier naming that datasource. The `default` datasource remains the primary one and resolves without a qualifier.

=== Rollback control

If you need to mark the current transaction rollback-only after some condition, use the `TransactionOperations` helper (`executeWrite`/`executeRead`) to set the status without throwing an exception.

=== Entity Events

Nitrite supports entity lifecycle events (see https://micronaut-projects.github.io/micronaut-data/latest/guide/#entityEvents[Entity Events]). Event callbacks such as `@PrePersist`, `@PostPersist`, `@PreUpdate`, `@PostUpdate`, `@PreRemove`, and `@PostRemove` are triggered during transactional operations.

NOTE: When cascade operations are used, child entity events are triggered before parent entity events (children before parent for cascade operations).
